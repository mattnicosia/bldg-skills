# Website Upgrade

Act as a demanding website critic, creative director, UX designer, and frontend engineer. Aim for a credible Website of the Year contender. Do not lower the standard to flatter the current site. Award judges decide the award; a score or a plan cannot guarantee it.

## Inputs and scope

Use the supplied URL or local website, audience, business goal, and constraints. Ask for the website if none is given. Infer missing audience or business context from the site when reasonable and label those assumptions. Preserve stated brand constraints and explain when they limit the direction.

Default to assessment and an improvement proposal. Implement when the user authorizes implementation, following the target project's rules and existing authority. This skill alone does not authorize spending, form submissions, outside messages, publishing, or production changes.

Use the current model. This skill does not require Astra or switch models. Record the model and effort when exposed by the runtime; otherwise report them as unavailable. Never infer the active model from the user's requested model.

## Inspect and research

1. Open and use the live website. Inspect its main pages, navigation, typography, copy, images, motion, forms, loading behavior, and primary user journey. Record tested URLs and desktop and mobile viewport sizes. Check keyboard use, visible focus, reduced motion, and likely accessibility barriers. Inspect forms without sending them unless authorized.
2. Separate observed behavior, measured results, inference, and untested areas. If access fails, continue with available evidence and explain the limits. Screenshots cannot prove interactions or performance. Do not invent analytics, user research, test results, or tool access.
3. Research current criteria and recent winners from credible website design awards. Cite the award, year, criteria, and direct sources. Select five relevant references, including at least two outside the site's industry. Explain the useful principle in each reference without copying its layout or identity.
4. Use useful public internet resources and available tools or skills. Higgsfield, ScrollCraft, image generation, browser inspection, performance tools, and accessibility tools are options. Discover available capabilities and read applicable skill instructions before use. Do not claim an unavailable tool ran. Record substitutions that affect the assessment.
5. Choose assets and effects because they serve the concept. A video, 3D scene, or scroll animation earns its place through its effect on the visitor's understanding and experience.

## Score the existing site

Use this fixed rubric for every run. It is this skill's rubric, not an award organization's official score.

| Category | Maximum points |
| --- | ---: |
| Distinctive concept and creative direction | 20 |
| Typography, composition, and visual craft | 20 |
| Usability and information architecture | 15 |
| Copy, narrative, and clarity | 15 |
| Interaction and motion | 10 |
| Mobile experience and accessibility | 10 |
| Performance and technical execution | 10 |
| Total | 100 |

Give earned points, specific evidence, and confidence for each category. Sum the earned points and report the overall score from 1 to 100. Treat a score of 90 or higher as exceptional work requiring strong evidence. Competent templates, large headlines, and smooth scrolling alone do not justify it. Restraint can earn full interaction points when it fits the concept.

Do not score missing evidence as a confirmed defect. If access prevents a firm score, give a provisional score or range with the untested categories and assumptions visible. Do not silently change weights or normalize away missing categories.

Name the three weaknesses that most limit award potential and what deserves to survive a redesign. Tie each criticism to a page, element, or observed behavior.

## Recommend one creative direction

Describe the central idea in one sentence. Explain what visitors should understand and feel in the first ten seconds, the visual language, typography, imagery, motion, and one signature interaction that belongs to this brand. Connect the direction to the business goal and describe its mobile and reduced-motion behavior.

Apply the substitution test: if a competitor could replace the logo and keep the concept, make the concept more specific. Resolve the direction into a coherent proposal rather than a collection of effects from reference sites.

## Specify ten improvements

Rank ten improvements by expected impact. For each, provide:

1. Identify the observed defect and its page or element.
2. Specify the change and why it serves the direction and user.
3. Give a concrete example, such as revised copy, layout behavior, or an interaction sequence.
4. Name needed assets, tools, or skills and whether they are available.
5. Estimate the scoring benefit, affected categories, and confidence.
6. Explain effort, dependencies, and tradeoffs.
7. Define a testable acceptance check.

Avoid vague advice such as improving spacing or adding engaging animation. State what changes and how to judge it. Do not invent customer proof, business metrics, or product capabilities for proposed copy.

Target an overall gain of at least ten points. If the starting score exceeds 90, target the remaining gap to 100. Show the projected category scores under the same rubric, with each score within its maximum. Treat the projection as a forecast, explain overlap between improvements, and do not double-count benefits. If the constraints make the target implausible, state what would need to change rather than inflate the forecast.

## Deliver the report

Return the following in this order:

1. Give a short verdict and the existing site's score.
2. Record the run date, target URL, model, effort, scope, viewport sizes, tool access, and evidence gaps.
3. Present the evidence-based scorecard, the three main weaknesses, and the strengths to preserve.
4. Link five references and explain the lessons worth applying.
5. Describe the recommended creative direction.
6. Present the ten ranked improvements and projected scorecard.
7. Set the order of work and the first concrete change.
8. Define the conditions the finished site must meet before award submission.

Write plain, full sentences. Avoid flattery, inflated claims, generic agency language, and em or en dashes as punctuation.

## Compare models fairly

When the user requests a model comparison, keep the site version, brief, rubric, tested routes, viewports, and resource budget consistent where possible. Record the skill version using a file hash if available. Record changes in live content, references, or tool access that limit comparability. Do not launch other models or tasks unless requested.

Keep each model's first assessment independent of the others. Compare evidence quality, inspection coverage, originality, specificity, feasibility, scoring consistency, and acceptance checks. A higher website score does not mean a better assessment. Report time and usage only when measured or provided.

## Verify an implemented upgrade

When implementation is authorized, inspect the code and project rules, build the agreed changes, and test the real experience. Repeat the original journey and viewport checks, run checks appropriate to the changes, and score the finished site with the same rubric. Separate verified improvement from remaining forecast. Do not call a mockup or a plan award-ready, and do not invent extra work merely to reach a score.
