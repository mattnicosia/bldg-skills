# Wow protocol (sites)

Impact, not decoration.

## Pass bar

Fails if a sharp visitor says "nice" and keeps scrolling.
Passes if hierarchy and one signature moment are obvious in two seconds.

A run that only a designer would notice in a diff viewer has failed this bar.

## Audit questions

1. What owns the screen in the first second?
2. Even and polite, or real scale contrast?
3. Material presence, or flat rectangles?
4. Is there a signature moment specific to this product?
5. Are states designed (hover, focus, loading, empty, error)?
6. Did motion change hierarchy, or only add movement?

Three or more "no / weak / none" answers → rescue mode.

## Rescue push (mandatory language)

When the page is weak, push all of these, not one of them:

- extreme hierarchy on the one thing that matters
- type with a real scale jump (display vs body, not +2px)
- material / depth / presence
- one signature moment tied to the product
- kill the safe middle

Do not invent a second product. Do invent a first impression.

## Protect push

Do not invent a brand unless asked. Amplify what is there.

## Landing / sign-in

- Hero must dominate immediately
- Sign-in is a premium moment, not a leftover form
- One job per viewport

## If this is NOVATerra

If the live page already uses charcoal + a committed accent (indigo/amber **or** the 2.0 orange), stay inside that system.

If the page is generic cards / default type / no owner of the viewport, rescue inside that system. Do not use "stay inside the system" as an excuse to ship an invisible pass.

## Anti-patterns

- more animation on an even layout
- generic cards, default type, soft gradient chrome
- rewriting IA to chase a look
- calling spacing or radius work a level-up
- restyling a working system because a new model arrived (protect mode only)
